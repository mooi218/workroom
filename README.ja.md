# Workroom

**仕事が見える、小さなオフィス。**

このパソコンの Codex プロジェクトで進む仕事を、役割ごとのピクセルオフィスで見渡すアプリです。仕事のタイトルが席の吹き出しに表示され、席を選ぶと担当内容と状態を確認できます。タイピングや音、コーヒー休憩などの動きも、好みに合わせて加えられます。

[English](README.md) · [ZIP をダウンロード](https://github.com/mooi218/workroom/archive/refs/heads/main.zip) · [リリース](https://github.com/mooi218/workroom/releases/latest) · [貢献ガイド](CONTRIBUTING.md) · [MIT License](LICENSE)

主な連携対象は、**このパソコンに記録された Codex の仕事**です。付属の ChatGPT Work 拡張は、対応する開いたページを観測する実験的な機能です。利用前に[連携範囲](#連携範囲と状態の意味)を確認してください。

## 起動する

1. [Node.js 24 以上](https://nodejs.org/)をインストールします。
2. 上の ZIP をダウンロードして展開するか、リポジトリをクローンします。公開済みの配布版は[リリースページ](https://github.com/mooi218/workroom/releases/latest)からも入手できます。
3. Windows は `start-windows.cmd`、macOS は `start-macos.command` を開きます。Workroom が起動し、ブラウザーでオフィスが開きます。

Windows・macOS・Linux 共通で、展開したフォルダーのターミナルからも起動できます。

```sh
npm start
```

実行時に追加パッケージを使わないため、`npm install` は不要です。Node.js は必要です。起動ファイルが開かない場合も、上のコマンドを使えます。

オフィスのアドレスは [127.0.0.1:4318](http://127.0.0.1:4318) です。利用中は起動したターミナルを開いたままにし、終了するときはそこで **Ctrl+C** を押します。OS への自動起動登録は行いません。

### サンプルで試す

画面の「デモを見る」を選ぶか、次のコマンドで架空の仕事だけを表示します。

```sh
npm run demo -- --open
```

席や音を試すとき、スクリーンショットを共有するときに使えます。実際の Codex の仕事を起動・変更することはありません。

## 仕事を見渡しやすくする

- **席の吹き出しで把握。** コンパクトな上部バーの下にオフィスのマップを置き、右側のパネルで仕事やチームの詳細を確認できます。初期表示は稼働中の仕事で、各席にタイトルと状態を表示します。表形式の仕事一覧も使えます。
- **オフィスだけを全画面に。** マップだけを広く表示でき、**Escape** キーで通常の画面に戻れます。
- **完了した応答を受け取る。** 受け取りトレイで、新しく完了した応答を確認して元の仕事へ戻れます。過去の完了項目を新着として扱いません。届くのは直近の応答の完了で、プロジェクト全体はまだ進行中の場合があります。
- **役割ごとに整理。** エンジニア・デザイン・広報・営業・編集・リサーチ・企画・運営などに振り分けます。独自の役割とキーワードを追加したり、仕事ごとに担当を指定したりできます。仕事に合わせて机と部屋が増え、4 席・4 役割の固定上限はありません。
- **複数の部署で工程を表示。** 現在のターンに複数の作業が記録されていれば、同じ仕事を複数部署に置きます。仕事の件数と席数は分けて表示します。
- **目的のプロジェクトを見つける。** プロジェクト・部署・状態で絞り込みできます。仕事やプロジェクトのグループ名も読み取りやすく表示します。
- **雰囲気を選ぶ。** 紺青のピクセルスタジオを基調に、文字の読みやすさにも配慮しています。ライト、グレーと黒のグラファイトダーク、緑を基調にしたダーク、端末に合わせる表示を選べます。
- **好きな動きを加える。** 音・アニメーション・立ち歩きは別々に切り替えでき、音量も調整できます。音と立ち歩きの初期設定はオフ。OS の「動きを減らす」設定も尊重します。
- **表示言語を選ぶ。** 初回は対応するブラウザー言語を使い、非対応の言語では英語を表示します。日本語・英語・中国語（簡体）・スペイン語・ポルトガル語・フランス語・ヒンディー語・アラビア語から切り替えでき、保存した選択を優先します。仕事の内容や追加した役割名は元の言語で表示します。

コーヒー、印刷、ソファでの休憩、睡眠などはオフィスの演出です。実際のツール操作を表すものではありません。立ち歩いても元の席に仕事の吹き出しと状態が残り、アニメーションをオフにするとすべての動きが止まります。

## 連携範囲と状態の意味

| 対象 | 自動反映の範囲 |
| --- | --- |
| このパソコンの Codex アプリ / CLI | 対応するローカル記録にある未アーカイブの仕事。複数プロジェクトと通常のサブエージェントを含み、内部の guardian レビューは除外します。 |
| ChatGPT Work | 付属の Chrome / Edge 拡張が、対応する開いたページで観測した仕事。Work の明示表示、または追跡対象の選択が必要です。 |
| 別のパソコンや未観測のクラウド作業 | 対象外です。クラウド全件をバックグラウンドで同期する機能はありません。 |

ローカルの記録は約 **2.5 秒**ごとに更新します。記録された状態を表示するアプリなので、元の仕事を開始・再開・停止・編集することはありません。

**「完了」は直近のターンの完了**です。プロジェクト全体が完了したという意味ではありません。15 分以上更新のない実行中の記録は、長時間の処理と停止した処理を区別できないため「未確認」にします。承認待ち・入力待ちの種類によっては、保存記録だけでは判別できません。

部署の判定には、現在のターンで観測できたツール名・変更対象・限定されたコマンド情報と、サブエージェントの明示的な担当を使う固定ルールを用います。そのターンで確認した部署を終了までまとめて表示するため、席の数が独立した AI の人数や厳密な同時実行数を表すわけではありません。コード内に直接書かれた呼び出しは静的に分類しますが、変数や分岐の実行結果は推測しません。未知のツールや間接的な操作を認識できない場合は、タイトル・担当名のキーワードで振り分けます。どちらの根拠を使ったかは詳細で確認できます。

Codex のローカル保存形式は変更される場合があります。対応できない記録は読み取り不能または未確認として表示し、Codex のデータを修復・書き換えることはありません。

### 実験的な ChatGPT Work 拡張

拡張は**自動ではインストールされません**。現在のインストール手順と画面の読み取りルールは、**実際の ChatGPT Work アカウントでは未検証**です。画面上の表示を観測する方式のため、クラウド全件の同期には対応していません。画面の変更で状態を読めなくなる場合があります。

1. Workroom を通常起動します。
2. Chrome / Edge の拡張管理画面で開発者モードを有効にし、「パッケージ化されていない拡張機能を読み込む」で `extension` フォルダーを選びます。
3. Workroom の設定で接続コードを表示し、拡張のポップアップに入力します。
4. ChatGPT の対象ページを開き、追跡を選びます。自動追跡は Work の明示表示を認識できる場合に限られます。

拡張はタイトル・会話 URL・表示状態をローカルのオフィスへ送ります。会話本文・Cookie・アカウントの認証情報は読み取りません。普通のチャットを自動で Work として扱わず、停止ボタンが消えただけで完了とも判定しません。約 **90 秒**観測が途切れたクラウドの仕事は「未確認」に変わります。閉じたタブ・休止したタブ・未観測のページの最新状態は確認できません。

対応する URL、権限、観測のルールは[拡張ガイド](extension/README.md)を参照してください。

## 設定とデータ

既定の読み取り元は `CODEX_HOME`、未設定ならユーザーの `.codex` フォルダーです。保存場所やポートを指定する場合は次のように起動します。

```sh
node server.mjs --codex-home /path/to/.codex --port 4318 --data-dir /path/to/workroom-data --open
```

- サーバーは `127.0.0.1` だけで待ち受けます。ネットワークへ公開せず、このパソコン内で使ってください。
- 接続用データは、既定では起動フォルダー内の `.workroom/` に保存します。接続コードを他人と共有しないでください。拡張は **4318** 番ポートに接続するため、利用時はポートを変更しないでください。
- テーマ・言語・音・独自の役割・担当変更はブラウザー内に保存します。クラウドの観測結果はサーバーのメモリ内にあり、再起動後は再び観測する必要があります。
- ローカルの記録から、仕事の情報と限られた作業情報を抽出します。会話本文・推論・ツールの引数や出力をブラウザーへ送りません。OpenAI の認証ファイルも読み取りません。
- 実際の仕事の記録、接続コード、私的なスクリーンショットは公開リポジトリに含めません。画面共有はデモ、報告例は架空の内容を使ってください。

> **利用量について：** Workroom の表示・分類・同期・演出は AI クレジットを消費しません。Codex / Work の仕事そのものには通常の利用量が発生し、アプリはパソコンの CPU・メモリなどを使用します。

## 開発・検証

Node.js とブラウザーの標準機能で動きます。オフィスは Canvas、音は Web Audio、状態の配信は SSE を使います。描画は見えている範囲に限定し、非表示のタブではアニメーションを止めます。オフィス本体と動くスプライト、通知音はコードで生成します。別途生成したスタジオの画像は、ヘッダーとフッターの細い装飾に使います。

数字と英語本文には同梱の IBM Plex Sans、日本語本文には同梱の Noto Sans JP を使い、Pixelify Sans はブランド表示に限定しています。フォントのファイルと OFL ライセンス文書もアプリに同梱しています。

```sh
npm test
npm run check
```

テストには合成した記録とローカル通信のテストデータを使い、Codex や ChatGPT へ仕事を送信しません。合成データでの拡張テストは、実際のページでの検証を意味しません。不具合報告や翻訳改善は[貢献ガイド](CONTRIBUTING.md)を参照してください。私的なログや作業データベースを添付する必要はありません。
